Enkeon Voice engineering audit — 2026-10-31

Verdict
The repository is an early native macOS product with useful foundations: isolated
speech/model helpers, on-device recognition enforced for Apple Speech, bound text
destinations, insertion verification, and conservative failure messages. It is not
yet justified to call it production-ready, state of the art, or hallucination-free.
This review found concrete correctness defects despite the original checks passing.

Scope and evidence
Reviewed the main dictation/controller, text insertion, completion, cleanup,
account/MCP, persistence, helper protocol, audio/provider paths and build/check
scripts. Inspected app integration and scanned UI/runtime code; this was not an
exhaustive visual/accessibility review of every screen. All source files were
untracked at entry; no commit, reset, deployment or app relaunch was performed.
Code-path findings below are distinct from observed runtime behavior. A successful
build does not verify macOS Accessibility interactions or browser OAuth races.

FIXED / HARDENED

1. P1 — Terminal edits could delete unrelated text.
   TextInsertion.replaceBeforeCursor only checked the prefix when AX supplied
   both value and cursor. Missing AX data fell through to repeated Backspace.
   It also checked only PID while deleting, not the actual field.
   Change: refuse this unverified terminal rewrite. The revision remains in the
   dictation record for copying. This intentionally removes unsafe convenience.

2. P1 — Snippets and memory expansions bypassed terminal newline safety.
   DictationController.insert used expansion text directly while only ordinary
   dictation went through terminal cleanup. Newlines/control characters could
   reach a shell. All terminal output is now sanitized before insertion.
   Regression includes CR, LF, Escape and Unicode line separator.

3. P1 — Cancelled dictation could still save a memory.
   cancel() invalidated interaction but did not cancel resultTask; remember()
   checked interaction only AFTER saveToMemory. Work is now cancelled and checked
   before the external save. A request already accepted by a remote service cannot
   be rolled back by local task cancellation.

4. P1 — Late transcript after a timeout could still be inserted.
   Timeout messages previously retained the interaction ID. Timeout now
   invalidates the interaction and stops the dictation engine.
   New dictation is also refused during finishing, preserving its bound context.

5. P1 — Completion acceptance could write into a different field.
   SentenceCompleter.accept captured the destination when Tab was pressed rather
   than preserving the field/value/range for which the suggestion was shown.
   Suggestions now carry a TextDestination and revalidate it before insertion.
   Typing through a suggestion reschedules it against fresh text. Acceptance and
   phrase feedback count only confirmed writes.

6. P1 — Revision application could alter an old field or paste elsewhere.
   apply() selected text on the old AX element before checking focus and allowed
   an unverified paste fallback. It now checks the focused element first and
   requires a verified direct destination. Live editor testing remains necessary.

7. P1 — Cleanup accepted changed numbers and negation.
   Numeric additions were exempt and one arbitrary added/removed word was allowed.
   Now numeric tokens must be preserved or map to an exact English spelled-out
   source value; negation changes are rejected, with explicit spoken correction
   handling for "no wait" etc. Arbitrary added words are rejected. This is a
   conservative lexical filter, not proof of equivalent meaning in all languages.

8. P1 — Weak retrieval could be inserted as a strong memory match.
   strongHit treated confidence in a fact as interchangeable with query relevance.
   It now requires top-level match_quality == strong and refuses explicitly
   outdated, dropped or broken hits. A strong match is still not proof that a
   stored assertion is true or answers the intended question.

9. P1 — Completion grounding allowed partial-name/number substring matches.
   "Ann" could match "Anna" and "25" could match "250". Attribution now uses
   token boundaries. Sentence-initial proper names no longer automatically escape
   checking; a limited list of ordinary sentence starters is exempt. Non-finite
   model log probabilities are rejected. Regression tests cover these cases.

10. P1 — Sign-out could be undone by an in-flight refresh/sign-in.
    Account operations now carry a generation and verify it before storing tokens
    or changing account state. Sign-out cancels pending operations. This has build
    coverage; delayed HTTP/Keychain integration races have not been exercised.

11. P2 — Failed Keychain replacement could destroy valid saved credentials.
    set() deleted the old item before adding its replacement. It now updates in
    place, adding only if the item does not exist. Keychain fault injection remains
    a follow-up; real credentials were not read or changed for this audit.

12. P2 — The 900 ms completion-memory timeout was not a true timeout.
    The task group scope waited for its child awaiting memoryTask.value even after
    cancelling it. Replaced with the existing first-result continuation helper.
    A regression checks that a 30 ms deadline returns in under 500 ms while the
    lookup sleeps for a second. The underlying lookup may continue until its own
    deadline; this fix bounds the UI wait, not all background resource usage.

13. P2 — Completion startup and memory state could outlive settings changes.
    Startup results are generation-checked. Disabling captures and stops the old
    server, so its delayed task does not clear a newer reference. Memory tasks and
    cache are cleared on account/privacy changes and field changes; grammar results
    check the current proofreading setting before being shown.

14. P2 — JSON containing the literal text "data:" broke MCP parsing.
    Parse JSON first before falling back to SSE handling; separate MCP text blocks
    with newlines. Regression includes the literal data: inside JSON content.
    Full incremental SSE parsing is still a follow-up.

15. P2 — Helper greeting could wait indefinitely; frames had unbounded lengths.
    An uncached hello now goes through the 5-second request deadline. FrameReader
    rejects JSON/payload lengths over 8 MiB and ignores further data after an invalid
    frame. Invalid frame regression included. This does not solve blocking pipe
    writes; see the remaining work below.

16. P2 — History loaded stale data even with history disabled.
    Startup now respects the setting, attempts removal, bounds loaded records to
    the retention limit, and writes with owner-only permissions. Deletion/save
    errors still need user-visible handling and persistence integration tests.

17. P2 — Failed undo was recorded as a successful undo outcome.
    Dictation records now use .undone only when undo succeeded.

18. P2 — Accessibility focused-element read forced an unchecked type cast.
    Verify CF type before casting. Other AX reads still need systematic range,
    type and messaging-timeout coverage against malformed/unresponsive editors.

19. P2 — Completion HTTP requests lacked explicit latency/error bounds.
    Health requests now have a one-second timeout and require HTTP 200;
    completion requests have a five-second request timeout and reject non-200.
    The overall startup loop is not yet a single wall-clock deadline.

REMAINING WORK, IN PRIORITY ORDER

P1: Audio callback must not perform blocking IPC.
BuddyDictationManager.installTap calls appendAudioBuffer directly; the helper
provider converts audio, serializes frames and synchronously writes a pipe under
SpeechHelper.writing. A stalled helper can stall this callback. Move to a bounded
single-producer buffer and dedicated sender; define overflow behavior, measure
lost frames, and test helper stalls/exit during capture. Do not replace this with
an unbounded Task per buffer.

P1: No current filter guarantees factual or semantic correctness.
CompletionGate relies on ASCII capitalized names/numbers, topic-word overlap and
model confidence. Lowercase facts, non-Latin names, dates, attribution and relations
remain weak. Cleanup can still reorder source words or drop meaningful content;
spoken rewriting relies largely on prompts, and grammar checking uses edit share.
Add a replayable corpus of negation, dates, names, multilingual speech, noisy audio,
prompt injection and unsupported facts. Evaluate raw transcription separately from
cleanup/rewrite. Keep source text available and show revisions for user review.
Use explicit extracted source spans for factual fills where feasible. Do not claim
zero hallucinations or 96% accuracy from a handful of synthetic clips.

P1: Thread safety needs dedicated verification.
AppleSpeechTranscriptionSession mutates finalization flags from callback/audio/
control paths without explicit synchronization. Other @unchecked Sendable helpers
need the same audit. Run Thread Sanitizer and deterministic start/stop/cancel tests;
serialize session state without holding locks across callbacks or model operations.
No data-race crash was reproduced during this review.

P1: Live insertion and clipboard matrix is absent.
copySelection cannot reliably distinguish the response to its Cmd-C from a new
user copy, then restores its old snapshot. Test clipboard images/files, focus
changes during paste, secure input, deleted windows, browser fields, Electron,
IME, composed Unicode, multiple monitors, and AX timeouts. Preserve uncertain
insertion as uncertain; never automatically retry and duplicate text.

P1/P2: Account and session lifecycle need integration fixtures.
LoopbackListener reads an HTTP request once, even though TCP can fragment it.
Cancellation before waiter registration can be lost. EnkeonClient initialization
can interleave across callers and the MCP session is not explicitly reset on
account changes. Inject network/Keychain dependencies and test fragmented callback,
parallel initialization, refresh rotation, sign-out during refresh, and project
switching. Validate metadata endpoint trust before following discovery URLs.

P2: Local model serving and downloads need hardening.
CompletionServer uses an unauthenticated loopback HTTP port, releases its probe
socket before server bind, and relies on a PID file/name check for cleanup.
Use per-launch authentication, explicit process identity/ownership, and a bounded
startup deadline. scripts/model.sh fetches a mutable model URL without checksum
verification. Pin revision + hash and record the model/runtime version in benchmark
results. scripts/llama.sh already pins a tag; do not blindly update it.

P2: Privacy and persistence deserve stronger product behavior.
History JSON is loaded/saved synchronously on the main actor and rewritten for
every record (up to 2,000 entries). Move persistence off the UI thread with ordered
writes and visible errors; consider SQLite only after measurement. PhraseMemory
privacy heuristics are not a complete secret detector. Add per-app learning consent
and clear delete/retention behavior. Completion prompts still include recent history
style samples; evaluate sample-copying before keeping that behavior enabled.

P2: Test/build/release engineering.
No CI workflow or XCTest target was present. Existing checks are preconditions
in a debug executable, not a full UI/integration suite. Add a supported macOS/SDK
matrix, a documented check command, release build checks, helper crash/hang tests,
signed-bundle tests, and code-sign/notarization/update verification before shipping.
Keep untrusted model responses out of logs; debug completion logs currently print
suggestions/memory excerpts. Build artifacts and source currently have no committed
baseline in this checkout, which makes later change review harder.

P2: UX/performance work should follow measured traces.
Record privacy-preserving durations for key-down-to-recording, first partial,
key-up-to-final, cleanup, insertion and confirmation. Track p50/p95/p99, memory,
CPU/energy and UI hitches. Make waiting/cancellation states predictable, preserve
raw words, explain unavailable language/model states, and keep onboarding one-time.
Use the real speech/editor corpus to select models; newest is not automatically
best on this Mac. The existing Apple SpeechAnalyzer path is a reasonable candidate,
not a verified winner against alternatives.

VALIDATION
Original EnkeonVoiceKitChecks passed before changes.
Expanded checks pass, including cleanup, grounding, parser, malformed-frame,
terminal sanitization and async timeout regressions.
Full Enkeon debug product build passes (final verification recorded in the session).
Existing speech-helper synthetic smoke check passes outside the sandbox:
  input: Send the Halvorsen pricing to Maria on Friday
  output: Send to Halverson pricing to Maria on Friday.
Its assertions only require send/pricing/maria/friday. This is a connectivity and
basic transcription smoke check, NOT an accuracy benchmark. Sandbox run reported
speech unavailable; unrestricted run reported available. No real microphone corpus,
live GUI injection, OAuth flow, Keychain failure, sanitizer, notarization or measured
end-to-end performance benchmark was completed. Helper sources were not changed.

PRIMARY REFERENCES CHECKED
Swift structured concurrency: task-group scope waits for children to finish.
https://docs.swift.org/swift-book/LanguageGuide/Concurrency.html
https://docs.swift.org/latest/documentation/swift/taskgroup/
Apple SpeechAnalyzer API and on-device transcription architecture:
https://developer.apple.com/videos/play/wwdc2025/277/
These establish API behavior, not this app's latency, accuracy or market ranking.
