Enkeon Voice — live AWS rewrite evaluation, 2026-11-01

Decision support
Claude Haiku 4.5 is the leading candidate for the next integration experiment:
it combined short response times with fewer concerning edits in our inspected
English examples. This is an engineering judgement, not a blind human preference
study. NONE of the tested configurations meets a zero-meaning-change release gate.
Do not silently switch the production editor based on this experiment.

What actually ran
Existing Enkeon AWS login, us-east-1, Bedrock ConverseStream, Standard tier.
No infrastructure was provisioned, no models downloaded, no application settings
changed. Only synthetic fixture text was sent; no microphone recordings, user
memory, credentials or real writing samples appear in the artifacts.

Baseline: 12 distinct fixtures, two rounds, four models = 96 successful requests.
English: natural wording, grammar, uncertainty, shortening, boundaries, casual
tone, source-text injection, ambiguous instructions, identifiers.
Spanish, German and French add limited multilingual probes (not language coverage).

Same system prompt per phase, temperature 0.2, max output 384 tokens; no retries,
no paid warm-up or model judge. Models were interleaved in seeded shuffled order.
Clock starts just before SDK invocation, ends after the response stream completes.
This includes network time from this Mac; it excludes application/backend/paste
latency. First text time is also recorded; final text time matters for safe edits.

Observed quality issues (manually inspected by the coding assistant)
- Ministral, ambiguous, both rounds: changed $400 to $450 despite an instruction
  to return the source unchanged when ambiguity cannot be resolved.
- Ministral, boundary, both rounds: dropped the inability to finish today and
  changed the draft offer to a question. Identifiers round 1 dropped Samir.
- Nova, ambiguous round 1: changed $400 to $500.
- Nova, German, both rounds: removed "not 14:30" from the explicit time contrast.
- Nova, concise, both rounds: made "please test it today" refer ambiguously to
  production, rather than clearly to staging.
- Qwen, boundary, both rounds: strengthened "I can send" into "I'll send".
- Haiku, concise, both rounds: dropped the explicit prohibition on deployment.
- Haiku, casual: returned the uncorrected sentence instead of fixing punctuation.
- Haiku and Nova, French: strengthened "could arrive" (pourrait) to "should
  arrive" (devrait), though both retained a caveat. Ministral added "around"
  (vers) to the date. Qwen better preserved that example's uncertainty.
- All four kept the instruction-like source text in the injection fixture;
  this single probe is not a comprehensive prompt-injection security evaluation.

Follow-up with stronger instructions
Added explicit checks for negative contrasts, can/will, might/should, immutable
amounts, vague requests, and no added greetings, apologies or promises. Used eight
new fixtures, two planned rounds, three candidates (Nova excluded after baseline).
Ministral and Qwen completed 16 each. Haiku completed seven, then received an AWS
ThrottlingException. The runner stopped Haiku instead of hiding the error with a
retry or another model. 39 successes + one error are retained in the raw artifact.

The stronger prompt did not solve semantic preservation:
- Ministral still removed the old time from a negative contrast, converted an
  offer into a promise, and changed "perhaps Friday" to "earliest Friday".
- Qwen still turned a conditional ability to send a preview into a commitment.
- All three dropped "Do not promise it today" from the refund fixture and added
  a new timing/service commitment. Haiku: "We'll process it as soon as we receive
  it." That is not equivalent to permission to refund only after the return arrives.
- Haiku again changed French "could" to "should".
These are failed cases, not cosmetic preferences. Natural prose alone is insufficient.

Account readiness
Read-only AWS Service Quotas inspection returned Haiku 4.5 cross-region RPM=10
(L-CCA5DF70), global cross-region RPM=10 (L-E5084BBA), and TPM=5,000,000.
No quota increase was requested. A separate eight-case Haiku follow-up is paced
at seven seconds between starts to finish the coverage without retrying the failed
request invisibly. Pacing time is excluded from request latency. Its raw evidence
is separate from the original throttled run.

Paced follow-up completed: eight successes, zero throttles; median 0.725 s,
sample p95 1.007 s. It still added the refund-processing promise, dropped the
old time in the English negative contrast, changed Monday to "by Monday", and
changed German "perhaps Friday, not Thursday" to "probably not until Friday".
This reinforces that Haiku is only a candidate, not a validated production choice.
Total across all phases: 144 attempted requests, 143 successful responses and
one throttle. Estimated inference cost from returned token usage: $0.02325344.

Reproduction and evidence
Runner: scripts/benchmark-bedrock-edits.py (requires existing boto3).
python3 scripts/benchmark-bedrock-edits.py --output /tmp/new-baseline.jsonl
python3 scripts/benchmark-bedrock-edits.py --suite holdout --models ministral14 qwen_next haiku45 --output /tmp/new-holdout.jsonl
Use --min-interval 7 for a single Haiku run under this account's current RPM limit.
Output files cannot be overwritten. Each records exact prompt, model IDs,
parameters, input, output, timing, usage, stop reason and failures.
Raw evidence and summary: docs/benchmarks/*2026-11-01*.
Literal checks deliberately do not claim semantic accuracy: a reformatted date
can trigger a false alarm, while an invented promise can pass every literal check.

Next integration requirements
1. Prefer Haiku 4.5 for further English editor development; retain the failing
   cases as regression fixtures. A recommendation is not a claim of production safety.
2. Validate proposed edits before replacement, preserving destination/text checks;
   reject empty, truncated or malformed responses. Numeric/name checks help but
   cannot alone detect deleted negatives or added commitments.
3. Evaluate a reliable meaning-preservation strategy on fresh messages; an extra
   model check must itself be measured for cost, latency and false negatives.
4. Implement the Enkeon-authenticated backend route and per-user request limits;
   AWS credentials must remain server-side. Address the 10 RPM quota before launch.
5. No automatic fallback or silent model change. Keep the source unchanged on
   rejection/failure and provide recovery. The current app has not been rewired.

Limits
Synthetic short texts, only four languages, few repeats, one Mac/network/region,
no blind human raters, no load test, and no integrated app/clipboard measurement.
No claim of SOTA, broad accuracy, zero hallucination or production readiness.
