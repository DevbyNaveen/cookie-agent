Method
Existing llama-server on the user's 16 GiB Apple Silicon Mac, Metal offload,
4 CPU threads, one request at a time, 2048-token context, 128 MiB prompt-cache
limit. Temperature 0, seed 42, cache_prompt=false. Synthetic prompts only.
18 distinct cases, one completed pass with a 768-token output budget including
reasoning. One warm-up excluded from summary. No app integration, microphone,
real memory store, AWS server or production traffic was exercised.

The initial 160-token trials were interrupted after discovering truncated
answers. Disabling reasoning did not change the observed behavior. The current
official card explicitly describes an always-reasoning model. These diagnostic
runs are saved separately and excluded from the final latency summary. The
original plan of two repetitions was replaced by one full-budget pass after
these diagnostics; this is not a stability or load test.

Observed results
- 17/18 requests returned nonempty final answers with finish_reason=stop.
- Median total request duration: 5.514 seconds, including the capped failure.
- Nearest-rank sample p95: 15.639 seconds; with n=18 this is the maximum, not a
  statistically reliable production tail-latency estimate.
- Median first visible answer latency among 17 nonempty answers: 5.089 seconds.
- Median runtime-reported decoding rate: 50.069 tokens/second, including reasoning.
  Token throughput therefore substantially overstates useful answer speed.
- Peak sampled server RSS: 1.837 GiB. This is not total system/GPU memory usage.
- Lowest sampled memory_pressure free percentage: 47%. No resource guard fired.

Quality review (assistant review against prewritten rubrics, not blinded scoring)
- Case 6: warmer bug-report reply invents a promise to keep the customer updated
  and omits that the fix timeline is unknown.
- Case 7: French grammar remains incorrect: "Elle ne veux" should be "Elle ne veut".
- Case 17: missing-memory bank-account completion returns no final answer even
  after the 768-token budget (15.639 seconds), instead of NO_SUGGESTION.
- Case 0: initial lowercase remains; minor correction completeness issue.
- Five memory-answer cases (11–15) satisfy their narrow fixture rubrics,
  including wrong-person, no-memory, conflicting-memory and injection cases.
  They do not establish reliable retrieval, grounded generation or zero hallucinations.
- French, Spanish, German and Chinese are tiny spot checks, not language qualification.

Safety and cleanup
The harness checked disk reserve and memory before starting, monitored memory,
server RSS and disk during execution, and imposed a five-minute deadline. Its
server bound to localhost and was stopped in finally. The verified temporary
model download was removed after saving results. About 14.95 GiB remained free
immediately afterward (other running apps can change this).
No application model routing, installed apps, private memory, or system settings
were changed. Added benchmark script and report artifacts only, plus a correction
to the research note about this model's reasoning behavior.

Next evidence needed
Test an explicitly non-reasoning candidate on the same fixtures, then use real
multilingual speech fixtures for ASR. Larger AWS candidates still require their
own GPU tests; these Mac measurements cannot establish AWS latency or cost.
