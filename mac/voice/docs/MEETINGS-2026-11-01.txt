Enkeon Voice meetings — implementation and verification, 2026-11-01

Implemented
- Floating bar hover: Speak, Meeting, Memory. Memory popovers keep their hover anchor visible while being used. Speak uses existing hands-free dictation. Meeting opens setup; Memory offers explicit branch-scoped recall and save.
- Separate audio-only ScreenCaptureKit stream for microphone and optional system audio. No screen output is registered or saved. macOS still requires capture permissions. Headphones are recommended to avoid acoustic duplication.
- Recording pill with elapsed time, pause/resume/stop, drag placement saved per display, and anchored catch-up panel. Recording stays explicit; no automatic call detection.
- Separate Parakeet helper and bounded PCM chunks (silence boundary after 6 seconds; hard boundary at 24 seconds). Dictation does not share its session or failure lifecycle. Continuous speech at the hard boundary can split a word; benchmark this with real calls before release.
- Per-track capture health; missing microphone pauses capture. Sleep pauses recording. Pause intervals and transcription failures appear as gaps.
- Audio chunks are persisted locally before transcription. Successfully transcribed audio is deleted; failed chunks remain for Retry audio. No playback archive. An unflushed in-memory tail of up to 24 seconds can be lost on abrupt termination. Restart marks interrupted meetings honestly.
- One atomic JSON record per meeting, private directory (0700) and file (0600). Recording history, transcript search, source timestamps, export, deletion and retry UI.
- Optional cloud notes and live catch-up use configured Claude Haiku 4.5. Consent is explicit in setup/notes. Audio never goes to this cloud request; transcript excerpts do.
- Haiku selects source IDs and categories; app supplies exact original transcript text. The first live test shortened a quoted passage and was rejected, leading to source-selection-only output. This guarantees copied source wording, not ASR truth, contextual completeness or correct classification.
- Notes are Highlights / Decisions / Actions / Questions; no speaker diarization or inferred task owner/deadline. Follow-up draft is built from reviewed source notes, editable and copyable, never automatically sent.
- Review for memory checks related records in the selected Enkeon branch. User chooses new memory or a specific prior memory to revise. Sources use enkeon-voice://meeting/<id>#<timestamp>. Local meeting deletion does not silently delete remote memories; UI discloses this.
- Use a meeting branch for writing; existing conservative sentence-prefix completion retains Tab/Esc. Eligible recalled saved meeting facts show meeting title and timestamp. This is exact grounded continuation, not arbitrary paraphrasing of any opening phrase.
- Menu bar meeting entry, working source URL routing and main-window reopening, and explicit active-recording quit protection. Existing shortcut/dictation/edit paths retained.
- Existing Enkeon directory-surface rejection now routes through tool_invoke only when the server explicitly says the requested tool is unavailable on that surface; network errors never trigger a potentially duplicate write.
- Found and fixed two main-thread Keychain waits during launch: editor credentials load in the background; account tokens load in the background once and are cached instead of read during UI rendering and every request. No credentials or Keychain permissions were copied or changed.

Verification
- Debug and optimized release app builds passed; release speech helper build passed.
- Existing kit regression suite passed, covering shortcuts, dictation, stale events, silence/quiet PCM, editing/model contracts and completion.
- New checks: atomic meeting persistence, 0600 permissions, recording gaps, source IDs, rejection of shortened/changed/unknown/gap evidence, chunk bounds, silence handling and pause/resume timestamps.
- Real local Parakeet batch on six seconds of synthetic speech: 0.0785 seconds after model readiness; includes Friday correctly. Not an end-to-end live-call latency claim.
- Live Haiku synthetic transcript check passed: two source-validated notes. No personal meeting data used.

Release limits / remaining validation
- Real-call microphone + system-audio capture, permission prompts, device switching, multi-monitor drag, long-session energy/memory and simultaneous dictation require physical-device testing.
- No automatic calendar/call detection, speaker-name assignment, audio playback archive or remote sharing/send integration. These were optional/later scope.
- No universal verified terminal replacement; existing safe Copy recovery remains.
- Existing personal direct Haiku key is reused. This is not a deployed multi-user Enkeon backend or billing integration.
- No claim that all older roadmap screens, dictionary cases, SOTA or latency/accuracy targets are proven complete.
- Automated screenshot capture of the app window was unavailable. Window-server inspection confirmed a main window and floating panel; stack sampling confirmed the final main thread was running its normal event loop instead of waiting on Keychain. Visual layout remains to be checked on the device.
