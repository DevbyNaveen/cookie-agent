Meeting-to-memory reliability pass — 2026-11-01

Changed
- Distinguish retrieval fact IDs from parent memory IDs. Structured mcp://agent source
  links supply revision targets and match saved meeting receipts for source labels.
  Unlinked extracted facts cannot silently become revision targets.
- Successful remember responses invalidate cached inline memories and attribution,
  including writes routed through tool_invoke. Account changes clear attribution too.
- Keep original transcript uncertainty in conservative sentence continuation.
- Give resumed recording a fresh microphone-health grace interval.
- Preserve audio when recognition returns empty, allowing retry; known gaps mark a
  finished meeting incomplete rather than fully transcribed.
- Reject stale/already-saved review sheets; prevent deletion and note regeneration
  during an in-flight memory save. A failed local receipt after remote success reports
  that distinction and blocks a duplicate save in the current session.
- Load healthy meeting records even when another record is unreadable; preserve the
  unreadable file and report the partial recovery. Validate record/file identity.
- Remove query and recalled-memory contents from completion lookup debug logging.

Validation
- Full EnkeonVoiceKitChecks passed after recovery changes.
- Regression fixture follows actual source selection, receipt parsing, persistence/reload,
  recall parsing, inline continuation and meeting timestamp attribution code.
- Includes conflicting continuation suppression, outdated result rejection, unlinked
  fact revision refusal, source URI validation, extracted ULID vs parent identity,
  resume health timing, and recovery with a corrupted file beside a healthy file.
- Debug app build passed; final concurrency/logging guard build also checked.
- No live remote memory was created, changed or deleted by the fixtures.

Limits
- Synthetic integration fixtures do not exercise a signed-in app network session, real
  microphone/system capture, GUI insertion or macOS permission transitions.
- Real account save/revise/recall and physical calls remain unverified. No meeting
  history records were present at the local status check before reload.
- Remote success followed by local disk failure still requires manual reconciliation
  after restart; a durable idempotent backend operation is needed for full guarantees.
- Broader backlog (capture callback ordering, device reconnect/restart, long-session
  performance, remote-memory deletion/cache freshness and server recall quality) is
  not certified by this pass. Existing raw audio tail recovery limit still applies.
