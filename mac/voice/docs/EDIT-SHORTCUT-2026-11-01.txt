Voice edit shortcut — 2026-11-01

User approved the Wispr-style Apple keyboard layout:
- Fn: dictation.
- Control+Fn: explicit voice editing. Hold Control first, then Fn, speak, release.
- Control+Command remains dictation for keyboards without a usable Apple Fn key;
  Option+Control+Command remains explicit editing there.
- Existing Option+Fn remains a compatibility alias.

Both Control/Fn press orders are recognized during the existing 200ms arming
window. If dictation has already begun, a late edit modifier cancels it with an
instruction rather than pasting the spoken editing command into the field.
Edit mode stays latched when the edit modifier is released before Fn. Fn release
ends the gesture; the remaining Control key does not start a second recording.
Shift combined with editing remains rejected as ambiguous. Control+Fn+Space does
not trigger hands-free. Existing Fn+Space and Shift+Fn behavior are retained.

Checks: EnkeonVoiceKitChecks passed with coverage of press order, release order,
late modifier cancellation, next-session reset, memory conflict and Space conflict,
alongside existing dictation, model and insertion checks. Physical Apple keyboard
events were not exercised automatically. App settings now describe the new chord.
This shortcut change does not add terminal input-buffer replacement support.
