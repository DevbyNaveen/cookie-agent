Enkeon personal Mac editor — direct Anthropic, 2026-11-01

User explicitly requested reuse of Cookie's Claude API key and Haiku.
Located Cookie's credential schema in cookie-launch/mac/Cookie/HarnessClient.swift:
service com.enkeon.cookie.provider-keys, account ANTHROPIC_API_KEY.
The credential was read in memory, verified against Anthropic, and copied directly
to Enkeon's separate Keychain entry (com.enkeon.voice.editor / anthropic).
No secret was printed, put in command arguments, source, logs, or a plaintext file.
Cookie's original entry and the former OpenAI entry were not removed.

CloudVoiceEditor now calls https://api.anthropic.com/v1/messages with pinned
claude-haiku-4-5-20251001, x-api-key, anthropic-version 2023-06-01, temperature 0.2,
and output_config.format JSON schema requiring one text field. No model fallback.
Only source text and edit instruction are sent, not microphone audio or memories.
Parser requires an assistant message, end_turn, one text block, valid JSON and
bounded nonempty text; refusals, truncation, failures and cancellation fail closed.
Existing destination and selection validation remain in the dictation pipeline.
Settings display Haiku/Anthropic; legacy openai preference migrates to anthropic.
This Mac's selected provider was set to anthropic after successful verification.

Scope
This is the user's personal key on their Mac, using Anthropic API billing directly.
It is not a shared credential bundled for customers, nor the planned Enkeon backend
route. A distributed subscription build still needs authenticated server-side usage.
Known semantic rewrite failures from the Bedrock evaluation remain relevant; this
provider switch is not a fix for every meaning-preservation issue.
