Enkeon Voice model research and release gates — 2026-10-31

Decision status
---------------
No combination has been verified to meet every saved requirement. “SOTA” on a vendor
benchmark is not evidence of <=4% WER and <=300 ms p95 in Enkeon on an M1.
This machine is an Apple M4 with 16 GB. Do not advertise universal accuracy,
zero hallucinations, Latvian quality, or M1 performance from these smoke checks.

Current routing
---------------
Dictation: Apple SpeechAnalyzer/SpeechTranscriber remains the configured default.
Apple's on-device SFSpeechRecognizer is its startup compatibility path. Speech
errors/timeouts no longer intentionally submit a partial transcript as a success.
No cloud speech is enabled. The optional older OpenAI audio-file implementation is
not the chosen speech architecture and is not claimed current or streaming.

Explicit voice edit: GPT-6.1 Terra, Responses API, reasoning effort none, structured
text result, store=false, bounded request/output, no retries or automatic fallback.
Selected text/message + instruction only. Original text remains on any failure.
Apple Foundation Models is an explicit alternative in Settings → Speech, not an
automatic substitute. Credential lives in Keychain. No shared key is bundled.
Cloud integration is implemented; live access, speed and quality are NOT validated.
The app's Enkeon login currently does not fund or proxy these provider calls.

Cleanup and grammar: existing Apple Foundation Models, with original-transcript
retention on cleanup rejection. Apple manages the on-device model version. The
speech-only timings below exclude cleanup, insertion, UI and recall latency.

Memory sentences: current strong structured recall hits, copied as a matching
sentence continuation, labelled “tab · memory”; conflicting matches suppress output.
Weak, outdated, dropped and broken hits are excluded. Matching prefix wording is
required. This deliberately does not provide arbitrary paraphrases of memory.
Stored memories themselves can be wrong or stale. No generative model is treated
as an authority for personal facts. General local Gemma completion remains when
memory mode is off; learned phrases and spelling suggestions remain available.

Speech candidate: Parakeet Ultra via FluidAudio/Core ML, pinned SDK revision
16d0a17471f3da6083b44aaea4c07d1989239140. Optional developer configuration only;
not promoted to default because local replay has missed the gates. About 630 MB of
model assets, downloaded separately. First Core ML preparation took minutes here.
SDK source is pinned; its downloaded model repository revision is not pinned by
our integration, so promotion also requires a reproducible weight manifest.

Primary-source comparison
-------------------------
OpenAI describes GPT-6.1 Terra as efficient and suited to drafting/revising text.
It supports no-reasoning mode, unlike the larger Astra/Sol variants. Luna is the
faster, cheaper focused-task option. Terra is our editing candidate, not a proven
winner against Luna on Latvian or p95. No account access is implied by documentation.
https://developers.openai.com/api/docs/guides/latest-model
https://developers.openai.com/api/docs/models/gpt-6-luna
Structured complete responses and refusal/incomplete handling:
https://developers.openai.com/api/docs/guides/structured-outputs

Anthropic Haiku 5.5 is another current low-latency candidate. Its docs describe
classification/routing/extraction workloads; that does not establish editing
fidelity or Latvian accuracy. No configured Anthropic credential was found in the
checked environment. It was researched, not called or benchmarked.
https://platform.claude.com/docs/en/models/haiku-5-5/overview

Google's Flash/Flash-Lite family is optimized for efficiency. Published output
tokens/second is not the time until a complete edit arrives on this Mac. It was
researched, not implemented as another fallback provider.
https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-6-flash-3-5-flash-lite-3-5-flash-cyber/

OpenAI now recommends gpt-transcribe for high-accuracy transcription and
gpt-live-transcribe for low-latency continuous transcription. New context fields
include languages, rather than blindly reusing the older singular language field.
Cloud speech would change the existing on-device privacy contract; it was not
silently enabled as a way to improve benchmark scores.
https://developers.openai.com/api/docs/guides/transcription

Mistral Voxtral 3 offers file and realtime transcription, but supported-language
counts differ by model/mode. The TTS language list is not proof of realtime STT
coverage. Its published realtime claims do not certify this product's release-to-
paste latency. No Mistral API evaluation was run.
https://mistral.ai/news/voxtral-3/
https://docs.mistral.ai/studio/audio/specs-and-limits/languages

NVIDIA Parakeet v3 supports 25 European languages including Latvian. Its model card
explicitly excludes Latvian from one cross-model comparison, so that comparison
cannot establish Latvian superiority. Moondream's Ultra post-training reports
improvements over v3 across its English, multilingual, noise and long-form groups.
Those GPU results are not equivalent to quantized Core ML results on this Mac.
https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3
https://huggingface.co/moondream/parakeet-ultra

FluidAudio publishes Core ML Ultra-v3 comparisons: better accuracy with similar
throughput, including Latvian improvement. That motivated integration and testing.
Throughput divided into clip duration is not a measured push-to-talk deadline.
Actual local results below overrule an inferred latency claim.
https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/ParakeetUltra.md

Qwen3.5-2B is a multilingual post-trained model with broader language coverage.
It is not a drop-in replacement for the current base-model continuation prompt
or token-confidence thresholds. A swap without evaluating the new prompt/template,
memory grounding, quantization and latency would be unvalidated. Not installed.
https://huggingface.co/Qwen/Qwen3.5-2B
The existing Gemma 3 1B model is not being labelled the current global SOTA:
https://ai.google.dev/gemma/docs/core/model_card_3

Apple advises checking supported languages/locales before using Foundation Models;
on-device availability does not establish multilingual rewrite quality.
https://developer.apple.com/documentation/foundationmodels/supporting-languages-and-locales-with-foundation-models

Validation protocol
-------------------
Actual helper binary, PCM16 mono 16 kHz, audio fed in 100 ms buffers at real speed.
Metric: last buffer/key-release to confirmed final event, excluding all downstream
work. Twelve baseline clips: 11 macOS synthetic English utterances across multiple
voices, names and numbers, plus silence. Six additional real Latvian FLEURS clips
were fetched from FluidInference/fleurs (lv_lv_0000 through lv_lv_0005). FLEURS is
Google's CC BY 4.0 dataset. These small subsets are smoke tests, not held-out
representative benchmarks. They are not an English/Latvian quality equivalence test.
https://huggingface.co/datasets/google/fleurs
https://huggingface.co/datasets/FluidInference/fleurs

WER uses the repository's existing punctuation/spoken-number normalization. It can
still penalize alternative time formatting (4.30 versus four thirty); inspect the
saved reference and hypothesis. Silence errors are counted separately from WER.
No aggregate across different language mixtures should be used to rank engines.
Background development builds may affect timing; these results are not a controlled
performance certification. No real user's microphone or private text was recorded.

Initial measurements
--------------------
Apple, 12 English/silence fixtures: 5.303% normalized WER; p50 72.6 ms,
p95 198.6 ms; no silence false positive. Names are the main weakness in this subset.
Parakeet full-utterance diagnostic, 18 English/Latvian/silence fixtures: p50 642.5 ms,
p95 1402.6 ms. This diagnostic is not the app streaming path. It changed 2002 to
2008 in one Latvian clip. Language support is not sufficient evidence of quality.
An initial default-window streaming attempt had 1–3.4 s release latency and failed
on a late volatile event after final; that integration bug was fixed. The corrected
short-window run and GPU-placement diagnostic are tracked in the result JSON files.

Corrected short-window streaming completed all 18 fixtures: p50 1308.9 ms, p95
2703.9 ms, no silence false positive. Separate normalized WER: English 3.03%
(11 synthetic clips), Latvian 27.52% (six real clips). Batch: English 3.03%,
Latvian 25.50%. These language-specific figures should not be replaced by a mixed
aggregate. The GPU diagnostic helper exited during preparation without a response;
cause unconfirmed, no GPU timing or accuracy result, no promotion.

The regression executable passed with the cloud transport mocked. An attempted
--live-cloud evaluation exited 2 with BLOCKED: no cloud editor API key in Keychain.
The complete app release build and pinned SDK/helper build compiled successfully;
final checks after cancellation/UI refinements are recorded in the session checkpoint.

Reproduce
---------
SDKROOT="$(scripts/sdk.sh app)" swift run --build-system native EnkeonVoiceKitChecks
SDKROOT="$(scripts/sdk.sh app)" swift run --build-system native EnkeonVoiceKitChecks --live-cloud
python3 scripts/bench.py --make-synthetic build/model-fixtures
python3 scripts/fetch-latvian-fixtures.py
python3 scripts/check-models.py --engine speech --clips build/model-fixtures --exclude latvian
python3 scripts/check-models.py --engine parakeet --clips build/model-fixtures
python3 scripts/check-models.py --engine parakeet --batch --clips build/model-fixtures
python3 scripts/check-models.py --engine parakeet --batch --gpu --clips build/model-fixtures

The live cloud command uses only synthetic fixtures, exits 2 when no editor API
key is in Keychain, and writes successful runs to build/model-evaluation. Its lexical
checks are necessary regression checks, not a semantic judge or a Latvian expert.
The ordinary suite tests mock transport: authentication, quota/server/network
failure, timeout, refusal, incomplete/malformed output, cancellation and input/output
bounds, as well as memory conflicts, negation, Unicode and stale recall filtering.

Promotion still requires
------------------------
Credential-backed cloud comparisons on English/Latvian instruction-following and
meaning preservation; the saved representative EnkeonDict set; M1 p50/p95 and
memory/battery; complete release-to-paste and memory-retrieval measurements; live
cross-app focus/cursor/clipboard/cancellation tests. Do not ask the user to debug
basic failures by treating an unmeasured model name as a finished product.
